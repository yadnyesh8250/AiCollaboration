Executive Summary

This RFC outlines our core architectural transition to Kafka / Redis PubSub clusters for peer presence sync, workspace state multiplexing, and diff-based document Conflict-free Replicated Data Types (CRDTs) with deterministic operational transform fallbacks.

1. Core Communication & Event Pipelines

In v2, all WebSocket frame synchronization relied on sticky-session socket hubs with monolithic in-memory state distribution. Under peak workspace collaboration spikes (e.g. concurrent document editing during all-hands reviews), packet latency reached 280ms with intermittent head-of-line blocking.

The updated v3 topology decouples client ingestion from state hydration: incoming operational delta events are ingested by lightweight stateless Gateway nodes running on Go, serializing mutations directly into Kafka partition topics keyed by doc_uuid.
